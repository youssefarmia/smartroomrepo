## Getting Started

### Prerequisites
- Git
- Python 3.10+ (with pip)
- Node.js 18+ (with npm)

### 1. Clone the repository
```bash
git clone https://github.com/youssefarmia/testrepository
cd smartroomrepo
```

### 2. Backend setup
```bash
cd backend
python -m venv venv
```

Activate the virtual environment:
- Windows: `venv\Scripts\activate`
- Mac/Linux: `source venv/bin/activate`

Install dependencies:
```bash
pip install -r requirements.txt
```

Run the backend server:
```bash
python -m uvicorn main:app --reload
```

The backend will be running at `http://127.0.0.1:8000`. You can view the interactive API docs at `http://127.0.0.1:8000/docs`.

### 3. Frontend setup
Open a **new terminal window** (leave the backend running in the first one):
```bash
cd frontend
npm install
npm run dev
```

The dashboard will be available at the URL printed in the terminal (usually `http://localhost:5173`).

### 4. User Guide

The Smart Room Dashboard gives you a live view of a simulated room and lets you control two devices in it.

**Sensor cards** 
- 🌡️ **Temperature** — drifts naturally over time, trending toward a baseline of 25°C unless the fan is running, which actively cools it down.
- 💧 **Humidity** — wobbles randomly within a realistic range (30–70%).
- 💡 **Light** — reflects whether the light is on (800 lux) or off (300 lux ambient).
- 🚶 **Occupancy** — randomly flips between occupied and empty over time, simulating someone entering/leaving the room.

**The room view** showing an image depending on the light and occupancy of the room, currently set to a placeholder.

**Fan and Light buttons** let you manually turn each device on or off. Clicking a button sends a request to the backend, which updates the device's real state — you'll see the button's label and the room view update once the backend confirms the change.

**Automations**
- If temperature rises above 26°C, the fan turns on automatically.
- If the room becomes unoccupied while the light is on, the light turns off automatically.

**Show History** reveals three things, fetched on demand:
- A **temperature chart** of recent readings over time.
- An **event log** listing every device change, manual or automatic, with timestamps and (for automations) a reason.
- An **energy usage** summary showing estimated watt-hours used by each device over the last day.

Click the button again to hide this section.

## Architecture Overview

- **Frontend (React + Vite)** is a thin client. It doesn't calculate anything itself — it polls `/sensors` and `/devices` on an interval and simply displays whatever the backend currently reports. Button clicks send POST requests; they don't update local state directly.
- **Backend (FastAPI)** is the single source of truth. An async background task, `simulate_room()`, runs continuously as long as the server is up — independent of whether any browser tab is open. It updates simulated sensor values every tick, checks automation rules (fan/light), and applies them directly to shared in-memory state (`sensor_state`, `device_state`).
- **Database (SQLite via SQLAlchemy)** persists two things: a snapshot `Reading` row each time `/sensors` is called, and a `DeviceEvent` row every time a device changes state — tagged as `manual` or `automation`, with a reason for automated ones. This is what powers the history chart, event log, and energy calculations.

This design means the room's state is consistent no matter how many browser tabs are open, survives page refreshes, and keeps running even with no frontend connected at all.

## API Reference

| Method | Endpoint | Description |
|--------|----------|---|
| GET    | `/health` | Basic health check. Returns `{"status": "ok"}`. |
| GET    | `/sensors` | Returns current sensor readings (temperature, humidity, light, occupied) and saves a snapshot to the database. |
| GET    | `/devices` | Returns current device states, `{"fan": bool, "light": bool}`. |
| POST   | `/devices/{device}/toggle` | Flips the given device's state (`fan` or `light`). Returns `{"device": str, "state": bool}`. Returns a 404 with a clear message if the device name is invalid. |
| GET    | `/history?limit=20` | Returns the most recent sensor readings, newest first. `limit` is optional (default 20). |
| GET    | `/events?limit=20` | Returns the most recent device events, newest first, including `triggered_by` (`manual`/`automation`) and `reason`. |
| GET    | `/energy` | Returns estimated watt-hours used per device over the last 7 days, calculated from device event history. |

Full interactive documentation (with request/response schemas and a "Try it out" button for each endpoint) is auto-generated by FastAPI and available at `/docs` while the backend is running.
